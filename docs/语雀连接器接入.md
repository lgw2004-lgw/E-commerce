# 语雀文档连接器

语雀通过本地只读 MCP 服务接入现有连接器页面，无需安装新依赖。服务只监听 `127.0.0.1:5671`；DB-GPT 仍使用 `5670`。

## 本地配置

在根目录 `.env` 填写，真实 Token 仅留在该文件：

```dotenv
YUQUE_TOKEN=自己的语雀访问令牌
YUQUE_API_BASE=https://www.yuque.com/api/v2
YUQUE_DOC_URL=https://www.yuque.com/用户名/知识库标识/文档标识
```

企业空间使用 Token 所属空间的 API 地址，例如 `https://your-space.yuque.com/api/v2`。文档地址与 API 地址须属于同一站点。`YUQUE_DOC_URL` 可留空：验收脚本会尝试从当前用户知识库选取第一篇文档，团队文档建议显式指定地址。接口和认证约定参照[语雀官方 SDK](https://github.com/yuque/sdk)和[官方 MCP 服务配置说明](https://github.com/yuque/yuque-mcp-server)。

运行 `start.cmd` 会在配置 Token 后启动本地 MCP 服务。已启动 DB-GPT 时，也可单独执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_yuque.ps1
.\.venv\Scripts\python.exe scripts/check_yuque_connector.py
```

更换 Token 或 API 地址后，先运行 `scripts/stop_yuque.ps1` 再运行 `scripts/start_yuque.ps1`，使服务加载新配置。`stop.cmd` 会同时停止本地 MCP 服务。

## 在系统中使用

验收脚本会通过 DB-GPT HTTP API 创建或更新同一端点的语雀实例，重复执行不会重复创建。打开[连接器页面](http://127.0.0.1:5670/construct/connectors)即可看到“语雀文档”。也可手动配置语雀模板：

| 配置项 | 值 |
|---|---|
| 传输协议 | Streamable HTTP |
| Endpoint URL | `http://127.0.0.1:5671/mcp` |
| 认证方式 | 无认证（Token 由本机 MCP 服务从 `.env` 加载） |

工具共四个：`yuque_get_user`、`yuque_list_repos`、`yuque_list_docs`、`yuque_get_doc`。最后一个工具接收完整文档 URL，返回标题和正文。在探索广场附加语雀连接器后，可输入：“请读取这篇语雀文档并总结：<文档完整地址>”。这一步需要在线聊天模型可用。

## 验收结果

`work/yuque-connector-check.json` 记录各阶段的真实结果：

- `transport_verified`：DB-GPT 完成 MCP 握手与工具发现。
- `account_verified`：通过 MCP 调用 `/user` 成功。
- `document_read`：通过 MCP 读到非空文档正文。
- `success`：以上步骤全部成功。报告只存标题、URL、正文长度，不存 Token 或正文。

页面“测试连接”只验证 MCP 协议连通，不能证明语雀 Token 权限或文档正文读取成功；应以完整验收报告为准。

HTTP 401 表示凭据被拒绝；403 需检查读取权限和 API 使用权限；404 需核对地址及可访问范围；429 表示上游拒绝请求，应等待后重试并检查语雀 API 配额、站点和网络。单凭 429 无法判断 Token 有效性。

离线验证：

```powershell
.\.venv\Scripts\python.exe scripts/test_yuque_connector.py
```

此测试使用模拟语雀 HTTP 响应，并启动真实本地 MCP 服务，验证 DB-GPT ConnectorManager 工具发现、带命名空间的工具调用及正文返回；它不代表真实语雀验收成功。
